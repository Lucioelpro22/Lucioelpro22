## Engineering principles

```text
least privilege      explicit policy       human accountability
fail closed          privacy by design     observable decisions
secure defaults      reproducible checks  documented limitations
```

My projects are intentionally defensive. They do not enable unauthorized access, covert monitoring, automatic retaliation, or unreviewed high-impact actions. Where automation could create harm, the system records a proposed action and requires an explicit, auditable approval.

## How I work

1. Define the threat model and safety boundary.
2. Build a small, testable core with deterministic behavior.
3. Add validation through tests, static analysis, dependency checks, and CI.
4. Document operational use, limitations, and failure modes.
5. Release incrementally and keep consequential actions human-approved.

## Public roadmap

- Keep CI, dependency auditing, CodeQL, and supply-chain checks green across the portfolio.
- Publish focused threat models and operational limitations for each project.
- Improve reproducible releases, SBOM evidence, and responsible disclosure guidance.
- Add interoperable examples without weakening privacy, human review, or fail-closed controls.
